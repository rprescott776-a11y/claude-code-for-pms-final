POLICY IN THE BRIEF

Count a miss more lightly

A handler-set "unavailable" never counts as quiet. The 60s wait is deferred, not endorsed; a 90s trial is a candidate test for Helen and Marcus.

Limits. I haven't seen the real console or phone app (ask Sofia for screenshots). Success targets in the brief are blank until Ravi provides ping-to-tap times. Handlers like Aunt Dot and Kip filed no tickets but still benefit, so the ticket metric will understate the gain.
Preventing a repeat

A review checklist now runs on every brief before it goes any further.

The eight checks

1Owner named5No contradictions
2Success measure6Claims trace to evidence
3Scope start = end7Open questions: owner + date
4Problem before fix8Metric measurable today

Output: Pass / Partial / Fail table plus ranked fixes. It never edits the brief. A scheduled task runs it every Monday ~9:06 on briefs in 05-super-speed.

How each check maps to what went wrong

4.2 failureCheck that catches it
Marcus's 14 Aug question sat unanswered#7 Open questions need owner + date

Two changes bundled, no clear success measure#2 and #8 Measure, measurable today
Stale briefs (Bulk Callout, Audit Log)#5 No contradictions

Limit: it checks briefs, not code. It won't stop a bad change from shipping — it makes the gaps visible before anyone commits.
